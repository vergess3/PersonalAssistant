Architecture
New text in one explicitly bound Weixin bot conversation -> this outbound-only
Node process -> exact existing Slack DM, one root thread per input ->
only replies from verified hilly user in that thread -> same Weixin peer/context.
No public listener, tunnel, incoming firewall rule, or model/API key.
This implements the Tencent-published wire protocol directly; it is not the
official plugin and is not yet proven against the live backend.
No OpenClaw installation is required by this prototype. Official plugin login
is an option, but installing it requires separate approval and runtime setup.

Behavior/limits
- Default CLI is offline; --live requires all configuration. No automatic login.
- Exact sender/receiver allowlist, no group handling, no old messages, no media,
  no quoted-message expansion. Missing required protocol fields are dropped.
  Required fields must be checked against actual authorized live sample data.
- Drops all messages older than process start, including downtime backlog.
  Pending threads/dedup are memory-only; restarting loses in-flight replies.
- Replies polled conservatively, usually 60+ seconds plus Weixin long-poll delay.
  Threads expire after 10 minutes. Multiple assistant messages can be forwarded;
  updates to already sent messages are not replayed. Final-answer streaming
  behavior still needs live validation.
- Maximum 10 pending threads, 10000 processed IDs per process, 4000 characters.
  No guarantee of exactly-once delivery. Ambiguous sends stop without retry.
- Weixin read failures back off; authentication errors stop. Slack rate limits
  currently stop the prototype. No unattended restart configured.
- stdout contains status only; no message bodies, credentials or context tokens.
- Node 25 is not a production LTS choice; choose supported LTS after approval.
- An authorized login returning a different Weixin host fails closed for review.
